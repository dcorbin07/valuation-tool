Valquo · research method

A quantitative equity and options research system, and the record of what it failed to prove.

Valquo is a personal research project, free and open to anyone: a point-in-time fundamental backtest over 2,531 US names and 69 quarterly rebalances from 2008 to 2026, an options study built on a mined contract history, and a live Flask app that scores the market daily. This page is about how questions get settled inside it — not about a return number.

The method

Every test writes its threshold down before it runs, and an ambiguous result is recorded as a null rather than argued into a win.

The hard part of this kind of research is not finding a pattern. It is deciding, in advance, what would count as finding one — because after the numbers are on the screen there is always a defensible reason to keep looking. So the protocol here is fixed:

  1. Commit the hypothesis and the pass/fail bar in writing, in the direction predicted, before the run. Several gates were committed as results-free git commits so the timestamp proves the order.
  2. Run it once on the full universe. Subsets are labelled smoke tests and never settle anything — a 30% subsample of this panel flattered its own overfitting statistic by a factor of four.
  3. Score the result against the bar as written. Ambiguous against its own threshold is a null, which is a verdict, not a judgement call.
  4. Append the row — especially the rejections. A log that records only adoptions is a multiple-testing denominator of one with extra steps.

Roughly 146 pre-registered tests have been run across the project. About one in eight was adopted, and the adoptions cluster in bug fixes rather than new signals. That ratio is the single most honest number on this page: it is what a real search over a finite dataset looks like when the nulls are not quietly dropped.

The append-only log that formalises this is recent and its retrospective backfill is not finished — which is recorded in the log, together with the reason a partial count has not been wired into the multiple-testing correction: a denominator of 30 carries the same false precision as a denominator of 8 while looking like it was measured.

Protocol and schema: RESEARCH_LOG.md (append-only, one row per pre-registered test). Universe rule: CLAUDE.md methodology section.

What the evidence killed

Seven ideas that were built, tested properly, and thrown away.

Each of these took real work — an EDGAR corpus, a mined option chain, a factor panel — and each is written up with the numbers that killed it. Publishing them costs nothing and is the only thing that makes the surviving results worth reading.

The uncomfortable one

A random-entry control beat the project's own options signal — and the result was written down rather than buried.

The app fires a "screaming buy" alert. To find out whether the day it picks is any good, each alert was paired with a random day in the same name and the same calendar year, using identical contract selection, fill and exit rules.

EntryTradesExpectancy per trade Profit factor
Alert day (the signal)3,042 +5.14%1.162
Random day (control)5,919 +11.07%1.373

Paired within name and year the alert loses by 3.72pp and wins only 44.5% of cells (sign-test z = −3.48), and it loses in both held-out halves by almost exactly the same margin (−5.88pp early, −5.96pp late). Nine corrected entry rules and six same-day filters were tested; all fifteen fail. Delaying the entry makes it monotonically worse, and fading it loses money outright, so it is not a timing offset and the tilt does not invert.

The caveat that has to travel with it

The control is a yardstick, not a tradable alternative — it buys weakness inside name-years that only exist because the alert fired there. So this says the alert picks a below-average day within the years it selects. It does not say the book loses to the market; that is a different question, and it is open.

HANDOFF_entry_fix.md — full run, 187 names, 2016–2025, gate committed results-free before the run.

Bugs, found and published

Six defects the project found in its own results, each recorded in the file it uses as memory — including the ones that invalidated headline numbers.

  • A price-basis defect underneath every options result. A dividend-and-split adjusted close was being fed into option maths that requires the as-traded price, in five call sites across four modules. Every options conclusion in the project was held pending the re-run rather than quoted in the meantime.
  • Five wired factors were silently empty — for the project's entire history. Return on equity, return on invested capital and asset turnover were non-null in 0 of 197,265 rows because the licensed export ships them only in a variant the loader never read; beta was hard-coded to None; a growth factor was overwritten with NaN downstream. The quality theme was averaging 8 of its 10 inputs with no error, ever. Two of the five turned out to be among the strongest signals in the panel. The fix shipped with a coverage guard that now fails loudly on any wired signal under 5% coverage.
  • A stale-quote settlement bias that would have handed a policy grid a fake winner. A position outliving its contract's last usable quote was marked at that quote — and a contract stops being quotable exactly when it is dying. On a hold-to-expiry policy, 44.6% of trades landed in that path, at a quote a median of 10 days before expiry; the stale mark beat true settlement 94.7% of the time, and 86.1% carried a positive mark on a contract that expired worthless. Correcting it cost that policy 6.45pp. The shipped exit touches it on 0.9% of trades, so earlier results survived — but only because they were checked.
  • A missing-data sentinel read as data. An open-interest value of -1 means "not available" and was being consumed as a number on 106 names, a median 12.2% of rows each — quietly faking liquidity, and gamma walls, on the names that mattered most. The guard originally written to catch it was itself blind on 82 of the first 109 names.
  • "The 800 largest names" was an alphabetical slice. The universe function sorted by ticker, not market cap, so a year of results labelled large-cap were companies beginning with roughly A through C. That invalidated a comparison the project had been repeating for months; every figure from that era is now flagged as needing a full-universe re-run.
  • Every value ratio was currency-corrupted. Market capitalisation arrives in USD while raw line items arrive in the reporting currency, so one foreign telecom's book-to-price computed as 892 against a true 0.589. It affected 4.1% of rows, and foreign over-representation in the top decile fell from 1.35× to 0.56× once fixed. A sanity layer now runs on every backtest: coverage says a factor is present, sanity says it is sane, and the currency bug filled every column, so coverage was blind to it.

Recorded in CLAUDE.md (the project's memory file, where wrong claims are corrected in place and the correction is called out), HANDOFF_edge_audit.md, HANDOFF_greeks.md, HANDOFF_ev_fix.md.

An outside audit, commissioned against the work

134 numbered findings, produced with read-only access, executed in dependency order.

An independent review was run against the repository at a named commit, with instructions to contradict the project record wherever the code disagreed with it. It produced 134 items — each with a hypothesis, an exact method, a pass/fail threshold committed before the run, and a file-and-line citation — plus a dependency map, because most items are only meaningful after the corrections they sit on top of have landed. A lane validator built from the real Python import graph checks that two parallel sessions working different items cannot touch the same modules.

It invalidated four things the project had been saying about itself. Each was corrected in the memory file rather than dropped:

  • The "deflated Sharpe ratio" is an undeflated one. Its benchmark scales with the variance of Sharpes across trials; the eight trials were eight near-identical weightings, so the variance was ~0 and the statistic saturated because it was deflating nothing. It now labels itself as undeflated in the output when that happens.
  • The one "out-of-sample confirmation" the model rests on is a both-halves stability check. The function computed its own pre-specified flag and then never read it — a demanding test, but not the test its docstring described.
  • The overfitting statistic scores only the weight-selection step, not the 116 logged equity trials that preceded it.
  • The headline number had never been tested as alpha. That one is now closed: the regression was pre-registered, run, and it cleared its threshold — see below.

What survives

Three results, each stated at the strength the evidence actually supports.

The composite's long-short spread has a t-statistic of 2.84 on the full 2,531-name, 69-date panel — below the 3.0 hurdle Harvey, Liu and Zhu propose for a literature with a multiple-testing problem. Three things travel with that number, and they point in both directions. An autocorrelation test rejects independence, so the figure this project quotes is the Newey–West one, t 2.62 — lower still. The rebalance grid is arbitrary, and re-run on seven equally valid ones the t ranges 2.70 to 3.52, straddling the hurdle rather than sitting on either side of it. But the long-short is not the object the Index actually is: the long-only top decile is much better measured, at t 4.38 Newey–West.

It survives trading costs, by about fourfold. The top decile's breakeven is 134 bps one-way against a measured cost profile of 33 bps, on 261% annual turnover. The breakeven is the number worth quoting because it requires no belief in any particular cost calibration — and the 33 is now measured from the panel's own market-cap cost table rather than assumed, which is not true of every cost figure this project has published. Borrow cost is not modelled, which affects the long-short statistic and not the long-only book.

And it replicates abroad, on another vendor's data, untuned. Five themes were mapped one-to-one onto public global factor data with no re-fitting of any kind, the country list fixed in writing first, and the bar set at Newey–West t > 2 in both target regions:

RegionAnnualisedNewey–West t
Japan+2.05%+3.85
Developed Europe (15 countries)+3.36% +4.30
World ex-US+3.37%+5.03
United States (control)+3.09% +2.35

All 15 European countries are positive and 12 of 15 clear t > 2. The striking line is the last one: the US — the only place any design decision was ever made — is the weakest region tested. That is the opposite of what overfitting looks like. It is out-of-sample in vendor, country, construction and period at the same time.

Reported rather than buried: two of the five themes do not generalise to Japan (quality contributes nothing there, momentum barely — a documented feature of that market), so the composite replicates while its composition does not.

The threshold that had to be cleared before the word "alpha" was used

The composite is roughly one-seventh each of value, quality, momentum, size, investment and institutional ownership — very nearly the standard factor set — so a spread against an equal-weighted universe could not, on its own, distinguish "we found something" from "we assembled the standard premia". Two claims were written out in full before the regression ran: one to publish if the intercept cleared Newey–West t > 2, and one to publish if it did not, in which case the honest description was efficient factor exposure and the word "alpha" stayed out of the copy entirely. An ambiguous result was pre-declared a null.

It cleared it. Against Fama–French five factors plus momentum, the headline series carries an intercept of +6.99%/yr with t = 3.98 (Newey–West, 68 non-overlapping windows, 2009–2025). All six pre-registered specifications are positive at t > 2, spanning +5.1% to +10.9%. The same pipeline run on a passive large-cap ETF returns +0.68%/yr, t 1.58, with a market beta of 0.93 and an R² of 0.99 — the placebo control that shows the machinery finds nothing significant when there is nothing to find. This is a backtest result and nothing more: it is not an expected return, not an achievable return, and not a return anybody earned.

The caveats travel with it, in the project's own words. It is still one panel — a factor regression is a control, not new data, and the international replication above is the out-of-sample evidence, not this. The t-statistic is not multiplicity-corrected against the 116 logged equity trials behind it (272 across the whole project), though the deployed weights are flat one-seventh and were never tuned. The panel's contaminated early period is no longer discounted — it was removed from the sample outright — and the conservative single figure is now the first half's +5.19%. And it does not contradict the null two sections up: beating the factor model is not the same as beating the ETFs a person can actually buy, and that second test was not passed.

Two further limits: the capacity of the strategy is roughly $4.9M as an upper bound — the same impact model as before, re-solved at the corrected breakeven above, which moved it down by nearly fivefold from the figure this page carried until 2026-08-08 — so it could never be a managed vehicle; and the small-cap tilt it carries is real, unhedged, and not costed for market impact at size.

The forward track

The only test that has not been contaminated by hindsight is the one that has barely started.

Every number above comes from data that existed before the rules were written. The single thing that fixes that is a forward record, so the app now runs one: a daily book against SPY and an options paper book that opens, marks and closes positions on its own.

Label, unmissably

It runs in a broker sandbox on a paper account. There is no real money in it, and never has been. It is days old, which is far too short to constitute evidence of anything, so no number from it appears on this page. It is listed here because starting the clock honestly — and admitting that the clock has barely started — is part of the method.

It is also the one dataset in the project that cannot be re-derived: it is a record of what the model said on days that have already happened. So it is exported to a committed, human-readable file on a schedule, with a guard that refuses to overwrite a real backup with a smaller one.

How it is built

Python, and a lot of tests whose job is to make silent failure loud.

  • The backtest engine builds nine themes point-in-time from licensed fundamentals, re-using the live app's own frame builder. That reuse is not complete, and the project says so: an open audit item records that the live path inherits two ranking options the backtest forces off, so no shipped code path reproduces the backtested composite exactly. It is logged as a known defect rather than left as an assumption. Weight selection is Combinatorial Purged Cross-Validation with a probability-of-backtest-overfitting readout, and if it rejects, the defaults stay — the selector is not allowed to talk itself into a weighting.
  • Guardrails as first-class output. Every run ships coverage, sanity, cost and point-in-time-freshness blocks alongside the results. Each exists because a specific bug got through: an empty column contributes nothing to a mean, raises no error, and lets the run complete normally.
  • A live Flask application on managed hosting with scheduled scans, a score-attribution panel that decomposes each name's rank into the themes that produced it (the explanation is computed from the same call as the score, and a test asserts the pieces sum to it), and email/Discord recaps.
  • 628 tests across 19 suites, run before anything merges. A representative test asserts that a sign convention is read the right way round, because it had been read backwards in the notes for months.
  • Written for the next reader. The project keeps an append-only research log, a per-session handoff file, and a memory file whose wrong claims are corrected in place with the correction called out — because a stale confident note is more expensive than no note.
